A Bitcoin Cash grant locked to a public block height and the beneficiary's signature. A standalone CashScript contract is the baseline. An XO template coordinates funding and release with the same spending policy.

Review the unlock height

The lock is an absolute block height, not a countdown. Funding late does not restart it.

Whole number from 1 to 499,999,999. Values of 500,000,000 and above are timestamps in Bitcoin Script, so they are rejected.

Who does what

Sponsor

Funds the grant output. Cannot spend it back and cannot move the unlock height after funding.

Beneficiary

Holds the key that signs the release. Can spend only once the chain reaches the unlock height.

Release rule

Spend requires tx.time ≥ unlockHeight and a valid beneficiary signature. Both must hold.

Review the migration evidence

The baseline and XO version were both authored during this build. The bounty asks for migration of an existing project or functionality but gives no pre-event publication cutoff. This baseline is presented with its true development history. Whether judges accept it as the original project is theirs to decide. Public project links and a funded Chipnet lifecycle are still missing.

Offline tests compare the CashScript and XO spending policies at, before and after the height and reject wrong keys and final sequences. They do not prove current chain maturity or an executed invitation.
